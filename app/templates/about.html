03. Problems & Solutions

데이터 품질을 해쳤던 4가지 문제와 그 해결.

#1 keywords=kw 데이터 오염 Before

검색어 "HVDC" → keywords 필드에 "HVDC" 저장. "자폐 그림책 앱" 논문에 #HVDC 배지.

After keywords="" (빈 값). 실제 논문 키워드만 저장. KCI-API는 API 제공 키워드 사용.
#2 KCI 관련 없는 논문 노이즈 Before

KCI 서버가 키워드 무시하고 최신 논문 50개 반환 → 영양학/암/식품과학 논문이 전력 검색어로 수집.

After post-filter()가 KCI-Web 논문 검증. 350개 → 2개 통과 (99.4% 제거).
#3 두 KCI 크롤러 이름 충돌 Before

kci.py → name="KCI", kci_openapi.py → name="KCI". Paper.source 동일, CrawlLog 서로 덮어씀.

After kci.py="KCI-Web", kci_openapi.py="KCI-API". 각각 로그/필터 가능.
#4 PA papers.db 동기화 실패 Before

git pull (merge) → binary 충돌로 papers.db 갱신 안 됨.

After webhook: git fetch + git reset --hard → 강제 동기화.

04. Architecture

4단계로 이루어진 데이터 파이프라인.

1
Collect
APScheduler가 매시간 6개 크롤러 실행. 각 크롤러는 키워드 목록 순회. source_url UNIQUE로 중복 방지.
2
Filter
수집 완료 후 filter_papers_by_keywords() 실행. KCI-Web 논문만 대상. 검색어가 제목/초록에 없으면 삭제.
3
Storage
papers.db (SQLite) — Git에 추적됨. pre-commit hook: commit 전 크롤러 실행 + git add papers.db.
4
Deploy
git push → GitHub Webhook → PA. git fetch + reset --hard. WSGI touch → uWSGI reload.
